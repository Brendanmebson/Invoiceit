Build on the Invoiceit API

Create invoices from your own store, till or scripts. How keys, tokens and retries work.

The Invoiceit API Live

The API lets your own systems write invoices into Invoiceit: an online store, a point-of-sale till, a booking form or a spreadsheet script. Invoices created through the API land in the same list as the ones your staff write, with the same numbering, totals and balances.

It's a REST API over HTTPS that sends and receives JSON. Every request is signed with an API key that belongs to one business, and it can only reach that business's invoices.

Start with the quickstart, then see every endpoint in the API reference.

API keys

Only the business owner can create and revoke keys. Staff accounts can't see them.

  • Shown once. The full key is shown a single time, when you create it. Invoiceit stores only a hash, so a lost key can't be recovered; revoke it and make a new one.
  • Format. Keys look like inv_live_ followed by 32 characters. In your account a key is listed by its first 8 characters, e.g. inv_live_3f9a12c0…, with the date it was last used.
  • Named. Give each key a name, such as "Online store", so you know which system uses it.
  • Up to 10 active keys per business. Revoking a key stops it working straight away.
  • Tied to your subscription. If your trial or paid period ends, your keys stop working until you pay. They don't need to be recreated.

Keep keys on your server. Never put one in a web page, a mobile app or a public repository.

Tokens and plans

The API is metered in tokens. One token is one invoice created through the API. Reading data, such as checking how many tokens you have left with GET /v1/usage, doesn't use tokens.

  • Every business starts on Free. The owner can upgrade in Business → API, where prices are shown in the business's currency. A paid plan lasts 30 days from payment; if it isn't renewed, the business goes back to Free.
  • Monthly allowance. Your tokens refill one month after the last refill, and also whenever you renew your Invoiceit subscription. Unused tokens don't carry over.
  • Failed requests are free. If an invoice can't be saved, the token is given back.
  • Out of tokens. Requests to create invoices are refused until your allowance refills. Your app and existing invoices keep working as normal.

Safe retries

Networks fail, and a retried request shouldn't create the same invoice twice. Send an Idempotency-Key header with any unique value (up to 255 characters) when you create an invoice.

  • Repeating a request with the same key and the same body returns the original response, and no extra token is used.
  • Reusing a key with a different body is refused, so a mistake can't overwrite an earlier invoice.
  • Keys are remembered for 24 hours.
